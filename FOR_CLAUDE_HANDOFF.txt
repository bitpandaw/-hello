【一句话系统概述】
  这是一个 **B2C 风格的全栈网上商城** 的毕业设计：用户端购物与订单流程、管理端商品/订单/用户/统计
  与 **RBAC 动态菜单**；后端 Spring Boot 3 多模块、MySQL 持久化、Redis 等支撑；两前端为 Vue3+Vite。

【逻辑架构（从论文「总体设计」角度）】
  1) mall-portal     — 顾客前台：商品浏览/搜索/购物车/订单与支付/会员与券等（页面见 portal 的 src/views）
  2) mall-admin-web  — 运营/管理员后台：登录后按权限加载侧栏、商品与订单等管理、仪表盘 ECharts
  3) mall-backend    — 统一 API：聚合业务接口、安全与 JWT、与数据库/缓存/MQ 交互；**可运行子模块
     是 mall-admin**（含 main），父 POM 为聚合、本身不可直接当 spring-boot:run 入口，论文里可表述为
     **分层与多模块以分离公共能力、安全与可运行端**；细节见代码与 README，此处只给结构认知。

【后端子模块（供论文里写「系统分层/模块」）】
  mall-common     — 通用模型、Result、错误码/成功码等；成功业务码 200
  mall-mbg        — MyBatis-Plus/代码生成与实体/Mapper 等（以仓库实际为准）
  mall-security   — 安全、JWT 等
  mall-admin      — 对外暴露 Controller、业务装配、**唯一启用的 Web 应用**

【后端业务面（看 Controller 包能概括「实现了什么领域」）】
  下列名称对应 mall-admin 下 *Controller 等，写「系统功能」时应对照代码/接口，勿凭空加子系统名：
  • 公开或前台相关：Pms（商品/分类等）、Oms 订单/购物车、Ums 用户、支付 Pay、券 Coupon、评论
  • 管理端 /admin 前缀：Auth、菜单 Menu、Pms/ Oms/ Ums 的 Admin*、统计 Stats
  • 文件：FileUpload（商品图等，静态访问 /uploads/** 类路径）
  更细的 URL 与权限，以各 Controller 注解和前端调用为准。

【C 端页面与论文「用户用例」对应（portal 的 src/views）】
  首页/分类/搜索/商品详情、注册登录、购物车、确认订单/订单列表与详情/支付、会员与地址/优惠券 等
  路径以 views 下子目录为事实来源。

【数据与持久化（论文「数据库设计」的锚点）】
  • 开发库名：**mall_dev**；连接信息见 mall-admin\...\application-dev.yml（**勿在公开文里复制密码**）
  • 全量与增量脚本：
      mall-backend\docs\sql\mall.sql
      mall-backend\docs\sql\mall_patch_v2.sql
    表名/字段/约束以这些文件与 mbg 实体为「事实」；`mall.sql` 与仓库中 mall-backend\mall.sql 有并行存在时
    以 **docs\sql\** 侧说明为论文引用优先。
  • 可选演示数据：mall_seed_demo_200.sql（样例 SPU/SKU/库存，有前置与 Workbench 安全模式说明，见文件头）
  • 表前缀/领域：PMS(商品/库存等)、OMS(订单/车)、Ums(用户)、以及 RBAC/菜单/统计在 patch 中体现
    具体表名在 SQL 中查；论文中的 ER/表结构描述应**对照** mall.sql 与补充脚本。

【前后端与接口习惯（论文「技术选型/接口设计」一句就够）】
  • 前后端分离；Vite 开发时把 /api 等代理到本机 8080（以各前端 .env 与 README 为准）
  • 成功响应码统一为 **200**；鉴权、刷新 token 等以 security 与 admin 的 Auth 流为准
  • 管理端：登录后 **GET 菜单** 做动态路由、RB；仪表盘含统计与图表类接口
